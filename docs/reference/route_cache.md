
# Route Cache

The route cache is generated by the matcher on first boot and read on subsequent requests.

## Warm the cache during build/CI

Pre-warm to avoid first-request latency spikes:

```bash
# Example: run your front controller once inside the image/container
php public/index.php --warm-routes
# or simply hit the app once via curl in CI/CD
curl -sf http://localhost/ >/dev/null || true
```

> Any request that boots the router will generate the cache if it's missing.

## Clear the cache

- **ShardedMatcher**: remove files under the configured cache directory, e.g.
  ```bash
  rm -rf var/route-cache/*
  ```
- **FusedMatcher**: delete the single cache file, e.g.
  ```bash
  rm -f var/route-cache.php
  ```

Regenerate by hitting the app or running your warm step again.

## Tips
- Ensure the cache path is writable at build/warm time but **read-only** at runtime in production images.
- Keep route **names** stable; renames cause cache invalidations and 404s for stale links.
- Pair with OPcache in production for best performance and low memory overhead.
